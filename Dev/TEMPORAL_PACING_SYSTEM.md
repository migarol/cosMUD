# Temporal Pacing System - Slow, Controlled, Balanced World Changes

## User's Critical Requirement

> "que todo sea muy cambiante pero no muy rapido no? puede tomar casi medio año en hacerse un nuevo town.. es lento, controlado, balanceado"

**Translation**: Everything very changeable but NOT too fast. Can take almost half a year to make a new town. Slow, controlled, balanced.

## Core Philosophy

✅ **World IS very changeable** (organic, dynamic, living)
❌ **World NOT instantly changeable** (no magical overnight transformations)
✅ **Realistic timeframes** (weeks to months for major changes)
✅ **Rate limits** (max changes per day/week/month)
✅ **Player actions matter** (but take time to have full effect)

## Time Scale System

### Real-Time to Game-Time Conversion

**Configurable Multiplier**: 4x (default)
- 1 real hour = 4 game hours
- 6 real hours = 1 game day
- 1 real day = 4 game days
- 1 real week = ~1 game month
- 1 real month = ~4 game months
- **~45 real days = 6 game months**

This means:
- Village → Town takes **6 GAME MONTHS** = **~45 REAL DAYS**
- Players will see GRADUAL progress over weeks
- Not instant, not glacially slow - BALANCED

### Construction Timeframes (Game Time)

## Rate Limits (Hard Caps)

### Per Day Limits

**Prevents sudden transformations**:

- **Max rooms added per day**: 3 rooms
- **Max NPCs spawned per day**: 5 NPCs
- **Max vital sign change per day**: ±5 points
- **Max gold injected per day**: 1000g (from Beeler)
- **Max items spawned per day**: 10 items

Example:
```
Village expanding to Town (needs +40 rooms):
- At 3 rooms/day max
- Takes minimum 14 days
- More likely 20-30 days (not every day builds)
- Feels ORGANIC, not instant
```

### Per Week Limits

- **Max new professions**: 3 new profession types
- **Max new skills**: 1 new skill
- **Max new resources**: 2 new resource types
- **Max area stage changes**: 1 (can't jump Outpost → Town in 1 week)

### Per Month Limits

- **Max new areas created**: 1 new area
- **Max areas reaching ruins**: 2 areas
- **Max wars declared**: 2 wars
- **Max trade routes**: 5 new routes

- **Start time**: When it began

- **Progress %**: Current completion (0-100%)
- **Visible to players**: Yes (they see it happening!)

## Player Impact Integration

### How Player Actions Affect Timelines

**Positive Actions** (Speed Up):
- Donate gold: -1 to -10 days per donation
- Complete construction quests: -3 to -15 days
- Protect from threats: -2 to -8 days
- Bring skilled NPCs: -5 to -20 days
- Diplomatic missions: -3 to -10 days

**Negative Actions** (Slow Down):
- Kill NPCs: +5 to +30 days (setback)
- Destroy buildings: +10 to +60 days
- Scare away workers: +3 to +15 days
- Steal resources: +5 to +20 days
- Cause safety issues: +10 to +40 days

**Example**:
```
Village → Town baseline: 180 days

Players help a lot:
- Donate 2000g total: -15 days
- Complete 5 quests: -25 days
- Bring 3 skilled NPCs: -30 days
- Protect from 2 attacks: -10 days

Total acceleration: -80 days
New timeline: 100 days (still >3 months!)

Players hurt it:
- Evil player kills 10 NPCs: +40 days
- Bandits steal materials: +15 days
- Monster attacks (undefended): +20 days

Total delay: +75 days
New timeline: 255 days (8.5 months!)
```

## Change Rate Limiting Implementation

### Daily Tracker

```c
struct area_daily_changes {
    AREA_DATA *area;
    int game_day;  // Current game day

    // Today's changes
    int rooms_added_today;      // Max 3
    int npcs_spawned_today;     // Max 5
    int vital_sign_changes;     // Track ±5 limit

    // Reset at midnight (game time)
};
```

### Enforcement

```c
bool can_add_room_today(AREA_DATA *area)
{
    if (area->daily_changes->rooms_added_today >= 3)
    {
        log_string("RATE LIMIT: Cannot add more rooms today");
        return FALSE;
    }
    return TRUE;
}

void add_room_to_area(AREA_DATA *area, ROOM_INDEX_DATA *room)
{
    if (!can_add_room_today(area))
    {
        // Queue for tomorrow
        queue_room_addition(area, room);
        return;
    }

    // Add room
    perform_room_addition(area, room);
    area->daily_changes->rooms_added_today++;

    log_string("Room added (2/3 today)");
}
```

## Beeler's Pacing Decisions

### Speed Selection

When Beeler creates/expands something:

```c
int beeler_choose_timeline(char *what, int urgency)
{
    // EMERGENCY (village starving)
    if (urgency >= 90)
        return SPEED_INSTANT;  // 1 day

    // URGENT (war, disaster)
    if (urgency >= 70)
        return SPEED_FAST;  // 1-2 weeks

    // NORMAL (expansion, growth)
    if (urgency >= 40)
        return SPEED_NORMAL;  // 1-3 months

    // SLOW (organic evolution)
    if (urgency >= 20)
        return SPEED_SLOW;  // 3-6 months

    // VERY SLOW (natural progression)
    return SPEED_NATURAL;  // 6+ months
}
```

**Most changes are NORMAL or SLOW**:
- Village → Town: SLOW (6 months)
- New district: NORMAL (3 months)
- Single building: NORMAL (3 weeks)
- Organic skill creation: SLOW (2-4 months)
- New area: SLOW (4-6 months)

**Only emergencies are INSTANT/FAST**:
- Village starving: INSTANT (create food immediately)
- City under siege: FAST (reinforcements in days)
- Plague outbreak: FAST (medical help in days)

## Benefits of Slow Pacing

### 1. World Feels Real
- No jarring overnight transformations
- Changes feel earned, not magical
- Consistency maintained

### 2. Player Agency Matters
- Players see their contributions accumulate
- Can influence outcomes over time
- Feel invested in world

### 3. Story Opportunities
- Ongoing changes create dynamic quests
- NPCs comment on progress
- Events during construction (celebrations, setbacks)

### 4. Balance Maintained
- Can't spam resources/NPCs
- Economy stays stable
- No sudden power spikes

### 5. Nostalgia & History
- Players remember "when this was just a village"
- Screenshot comparisons over months
- Shared history with other players
